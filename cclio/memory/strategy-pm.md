Branch of [[dima-strategies]]. Linear projects: `pm`, and the tracker context docs.

## the aim

**A chiller loop, not a fuller board.** Dima: «you are intended to optimize flow not make it hotter.
you have powerful capabilities and use them imprecisely.» The measure of this branch is not how much
is captured — it is how much has been retired, and how little of his attention each retirement cost.

## the strategic problem

Capture is cheap for an agent and retirement is expensive for a human. Left alone the board grows
monotonically and the heat never comes down. Powerful tooling makes this worse, not better: a sweep
finds real things, files them correctly, and leaves the debris. Every correct action can still
degrade the system.

## the moves

- default verb is fold or drop, not file → [[pm]]
- placement decided before creation, never repaired after → DOT-182 gate
- one flush per session; batch drafts, one approval
- act proactively but sit chill, even in the most stressful scenario — this is a standing
  instruction about *manner*, not just method
- the `freebie` label is the delegation escape hatch: pre-approved work that can run while he is away

## where it is heading

The tracker should eventually be something he reads for orientation rather than processes as a
queue. Milestones are on the table as a fun-but-optional layer. The linear structure revamp (DOT-72)
and the horizon sweep (DOT-149) are the vehicles.

## how it interacts

Every other branch produces tickets, so pm is where the other five become visible. If pm is hot,
every branch feels hot. That is why it is not "the admin branch" — it is the one that determines
whether the rest feel chill.
