# dima's strategies — the branch map

The CEO-altitude view. [[dima-stories]] holds what happened; this holds **where it is all going**.

**Why pm needs this:** a ticket decision made without knowing which branch it serves is how the
tracker drifts. Placement, priority, folding, and what earns a spawn all depend on the branch. When
Dima says «where are we», the honest answer is per branch, not per ticket.

**All branches are equally weighted.** None is the main one; none is a side quest. They advance at
different speeds because of quota, mood and blockers — never because one matters more. Do not
silently promote the branch that happens to be in front of you, and do not apologise for a branch
that has been quiet.

## the branches

- [[strategy-pm]] — the tracker and the flow that runs it. optimize flow, don't heat it.
- [[strategy-fleet]] — the agents themselves: surfaces, memory, skills, the coordinator migration.
- [[strategy-dimas-tools]] — his own machine: git, shell, nvim, dotfiles. the tools he and the
  agents share.
- [[strategy-bytes]] — the bytes team and its projects. real product work, currently starved.
- [[strategy-harness]] — the home-baked orchestration harness. wanted, deliberately deferred.
- [[strategy-visibility]] — seeing what the agents are doing. after mvp, explicitly.

## the order

The branches say what the work is about. **[[dima-roadmap]] says what we do next** — Dima's own
sequence, kept evergreen. Read both: a branch without the order invites picking the fun one, and
the order without the branches loses the why.

## how to use it

- before creating a ticket, name its branch. If it fits none, that is a signal — either the branch
  map is incomplete or the ticket should not exist.
- when reporting, give the branch a line each, including the quiet ones. Silence on a branch reads
  as abandonment.
- when Dima steers, ask which branch it steers. He often gives a move without naming the branch,
  and the same move means different things on different branches.
- a branch is not a Linear project. Projects are storage; branches are direction. Several projects
  can serve one branch.
