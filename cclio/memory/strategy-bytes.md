## the aim

Actual product work on the x-com products — bytes, numi, sline, plugin-x. The thing all the agent
infrastructure exists to serve.

## the strategic problem, stated plainly

**«did not even touch bytes for the last week.»** — Dima, unprompted, in the same breath as
describing the pm heat.

That sentence is the branch's whole status and its whole risk. Every other branch is meta-work:
tooling that makes work easier. Meta-work is more legible, more satisfying to sweep, and it never
finishes. Bytes is the branch that loses when the others feel productive.

## how to hold it

- **surface it.** Bytes going quiet is not neutral. Mention it in reports even when nothing changed
  — especially then. A branch nobody names is a branch being abandoned by default.
- **do not fix it by adding bytes tickets.** More tracker entries is the pm failure mode, not
  progress. What this branch needs is sessions, not backlog.
- when the fleet mvp lands, the honest test of whether it worked is whether bytes gets touched more.
  That is the outcome measure for the whole system, not context size or ticket counts.
- BYT tickets follow the same conventions as DOT; team key is the only difference. Never guess a
  BYT id.

## note on distance

He says «we're far from them» about bytes projects — that is a statement of current distance, not of
priority. Equally weighted. Do not treat it as parked.
